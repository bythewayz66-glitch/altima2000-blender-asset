# ALTIMA2000 — 2000 Nissan Altima (L30) fully disassemblable Blender asset

A procedurally generated, photorealistic 2000 Nissan Altima sedan in **gold metallic**,
split into **1,539 individually selectable, separately named parts** organised into a
**51-collection** tree, with a machine-readable assembly manifest, a working
disassemble / reassemble toolkit, a **12-step engine-bay exploded assembly sequence**,
a **standalone door module**, and a **modular export** (six system `.blend` files plus a
top-level assembly file that links them).

Everything here is generated by Blender Python — there is no downloaded or third-party
mesh in the asset. Running the build script reproduces the whole car deterministically.

## 2. Naming convention

Every object name matches this regex, enforced at build time (`bad=0` on every build):

```
^ALTIMA2000_[A-Z0-9]+_[A-Za-z0-9]+_[A-Za-z0-9_]+$
```

Human-readable form:

```
ALTIMA2000_<GROUP>_<Tag>_<Detail>[_<NNN>]
```

| Field | Meaning | Examples |
|---|---|---|
| `ALTIMA2000` | Fixed asset prefix. | |
| `<GROUP>` | 3–4 letter system code (table below). | `BODY`, `ENG`, `FAST` |
| `<Tag>` | The component family / assembly. | `Door`, `ValveCover`, `Bolt` |
| `<Detail>` | Variant within the family — usually the corner. | `FL`, `FR`, `RL`, `RR`, `Front`, `Rear_Left` |
| `_<NNN>` | Zero-padded sequence, **only** when a family has more than one instance. | `_001` … `_170` |

Corner codes are always from the driver's perspective: **F**ront/**R**ear + **L**eft/**R**ight,
so `_FL` is the front-left corner. `_L` / `_R` alone mean "left side / right side".

```
ALTIMA2000_Interior      → Interior_Dash, Interior_Seats, Interior_Console,
                           Interior_Trim, Interior_Insulation
ALTIMA2000_Electrical    → Electrical_Harness, Electrical_Battery, Electrical_Modules,
                           Electrical_Lighting
ALTIMA2000_Fasteners     → Fasteners_Bolts, Fasteners_Nuts, Fasteners_Clips
ALTIMA2000_Glass         → Glass_Glazing, Glass_Mirrors
```

Each sub-collection matches exactly one **assembly block** — a spatial group of parts that

## 5. Engine-bay exploded assembly sequence (12 steps)

The engine bay ships with a **12-step exploded assembly sequence** ordered exactly the way
a KA24DE is built — bottom-up. Playing the steps **forward explodes** the bay in assembly
order; playing them **backwards reassembles** it.

Each step owns one named empty, parented to a single root empty:

```

├── ALTIMA2000_SEQ_Step01_EngineBlock
├── ALTIMA2000_SEQ_Step02_Crankshaft
├── ALTIMA2000_SEQ_Step03_Pistons
├── ALTIMA2000_SEQ_Step04_CylinderHead
├── ALTIMA2000_SEQ_Step05_Camshafts
├── ALTIMA2000_SEQ_Step06_TimingSet
├── ALTIMA2000_SEQ_Step07_IntakeSide
├── ALTIMA2000_SEQ_Step08_ExhaustSide
├── ALTIMA2000_SEQ_Step09_CoolingSystem
├── ALTIMA2000_SEQ_Step10_AccessoryDrive
```

Each empty carries its own metadata as custom properties, so the sequence is
self-describing inside the `.blend`:

| Property | Meaning |
|---|---|
| `kind` | `sequence_step` (or `sequence_root` on the root) |
| `step_index` | 1–12, the playback order |
| `step_key` / `step_title` | Short key and human title |
| `explode_dir` | Unit vector the step's parts travel along |
| `explode_distance` | Travel distance in metres |
| `part_count` | How many parts this step moves |
| `parts` | Comma-separated list of the exact part names it moves |
| `note` | What the step represents in the build |

### Driving the sequence

The empties are animation targets: keyframe `location` on each one, or drive them from
Python. The shipped operators (in `altima2000_assembly_tools.py`, **Altima 2000** sidebar
tab) are:

| Operator | Blender id | What it does |
|---|---|---|
| Apply Sequence Step | `altima.sequence_step` | Explodes (or restores) one step. Params: **Step** 1–12, **Reverse**, **Distance Scale**. |
| Apply Full Sequence | `altima.sequence_all` | Plays all 12 steps in order. **Reverse** reassembles. |
| Reset Sequence | `altima.sequence_reset` | Returns every sequence part to its stored assembly position. |

```python
# explode the whole engine bay in assembly order
bpy.ops.altima.sequence_all(reverse=False)

# play it backwards to reassemble
bpy.ops.altima.sequence_all(reverse=True)

# or drive one step at a time
bpy.ops.altima.sequence_step(step=4, reverse=False)   # cylinder head off
bpy.ops.altima.sequence_step(step=4, reverse=True)    # cylinder head back on
```

Forward and reverse are exact inverses: the round trip restores every part to within
**6.1 × 10⁻⁷ m** of its build position (verified, see §11).

## 9. Disassemble / reassemble / explode

The `.blend` ships with the assembly operators. Open the file, run
`altima2000_assembly_tools.py` once from the **Text Editor** (*Run Script*), then use the
**Altima 2000** tab in the 3D Viewport sidebar (press `N`) — or the operator search (`F3`).

| Operator | Blender id | What it does |
|---|---|---|
| Disassemble (Explode View) | `altima.disassemble` | Radially displaces every part away from the explode centre, storing each part's assembled position first. Params: **Distance** (0–5), **Centre**, **Selected Only**. |
| Reassemble (Assembly View) | `altima.reassemble` | Restores every part's location and rotation from its stored `asmb` transform. |
| Verify Assembly | `altima.verify_assembly` | Checks every part against its stored position within a tolerance and reports any that are misplaced. |
| Apply Sequence Step | `altima.sequence_step` | Explodes / restores one engine-bay step (§5). |
| Apply Full Sequence | `altima.sequence_all` | Plays all 12 engine-bay steps, forward or reverse. |
| Reset Sequence | `altima.sequence_reset` | Returns every sequence part to its assembly position. |

Typical loop: **Verify Assembly → Disassemble → Reassemble → Verify Assembly** (the last
check confirms the car returned to its exact build state).

### How the reassembly actually works

Every part carries a custom property `asmb` (visible in *Object Properties ▸ Custom
Properties*) holding its canonical transform:

```json
{
  "loc": [0.12, -0.781, 0.688],
  "rot": [0.0, 0.0, 0.0],
  "collection": "Body_Panels",
  "part": "Side_R",
  "group": "BD",
  "sub": "Side",
  "template": ""
}
```

`"template"` is non-empty when the part shares its mesh datablock with siblings (fasteners,
clips, hoses) — see §10. So reassembly is exact and **does not depend on the manifest file**;
the manifest is a second, external copy of the same data.

### Reassembling programmatically

```python
import bpy, json

manifest = json.load(open("altima2000_manifest.json"))

for row in manifest["parts"]:
    ob = bpy.data.objects.get(row["name"])
    if ob is None:
        continue
    ob.hide_viewport = ob.hide_render = False
    ob.location       = row["offset_m"]
    ob.rotation_euler = row["rotation_euler_rad"]
    ob.scale          = row["scale"]
```

Or straight from the `.blend`, with no manifest at all:

```python
import bpy
for ob in bpy.data.objects:
    info = ob.get("asmb")
    if info:
        ob.location       = info["loc"]
        ob.rotation_euler = info["rot"]
        ob.hide_viewport  = ob.hide_render = False
```

| `part_count`, `collection_count`, `material_count` | Summary counts |
| `collection_counts` | Parts per sub-collection |
| `group_counts` | Parts per system code |
| `collection_tree` | category → sub-collection → count |
| `instance_families` | Mesh datablock → number of objects sharing it |
| `sequence` | **The 12-step engine-bay sequence** (root empty, step count, order, bay centre, total parts moved, unclaimed parts, and per-step `empty` / `key` / `title` / `explode_dir` / `explode_distance_m` / `part_count` / `parts` / `note`) |
| `modules` | **Per-module report** (file, root collections, collections, part count, part names, object count, size, open/parse result) plus `_assembly` (file, mesh object count, per-module link resolution, `all_modules_linked`) |
| `parts` | **The list of all 1,539 parts** |

Each entry in `parts`:

| Field | Meaning |
|---|---|
| `part_index` | 1-based order of creation |
| `name` | Object name (matches the naming regex) |
| `collection`, `group`, `sub`, `part` | Where it lives and what it is |
| `material`, `material_key` | Material datablock name and build key |
| `instance_of` | Shared template mesh name, or `""` if the part owns its mesh |
| `position` / `offset_m` | **Assembly position of the object origin**, metres |
| `rotation_euler_rad`, `scale` | Assembly rotation and scale |
| `assembled` | `true` when the part is in its assembled state |

`altima2000_manifest.csv` carries the same part fields, flattened, with
`ox,oy,oz / rx,ry,rz / sx,sy,sz` column triplets.

## 10. Why 1,539 parts but 717 meshes

A real car has thousands of identical fasteners. Modelling 1,539 unique meshes would be
wasteful, so bulk families (bolts, nuts, clips, hoses, tie straps, fuses) share one mesh
datablock per size/template while remaining **1,539 separate objects** — each still
individually selectable, individually named, individually transformable, and each with its
own manifest row. The manifest's `instance_of` column tells you which objects share a mesh;
`instance_families` gives the counts per template.

Result: 41,632 vertices / 42,743 faces for the entire car, ~2.0 MB glTF.

## 13. Rebuilding from source

The whole car regenerates from the scripts in `source/`. Blender 4.5 LTS, no add-ons,
no external assets.

```bash
cd source
ALTIMA_OUT=/path/to/build ../blender-4.5.14-linux-x64/blender -b --factory-startup --python build_altima.py
```

## 14. Known limitations

- **Body panels are surface shells**, not solid stampings: each panel is a correctly
  shaped, correctly placed skin with real thickness via a Solidify pass, not a modelled
  inner pressing with ribs and flanges. Panel gaps are geometric, not stamped flanges.
- **Fastener and clip positions** are distributed deterministically across each
  assembly's bounding volume rather than derived from real torque-spec locations.
  They are correctly named, grouped, counted and transformable, but a purist concours
  teardown would want them individually placed.
- **Engine internals** (crank, cams, pistons) are representative volumes at correct
  positions and orientations, not dimensioned to factory drawings.
- **The 12-step sequence covers the engine bay only** (230 of 1,539 parts). The remaining
  1,309 parts are moved by the whole-car `altima.disassemble` operator, not by a step.
- **Interior** is modelled to the visible surfaces plus seat structures; underside
  bracketry is simplified.
- Renders are Cycles CPU at 28 samples — clean enough for verification, not for
  marketing.
